# CONTEXT — nalam.me

Domain vocabulary for this repo. When naming things in code, issues or commits, use
these terms. Where a term has a tempting synonym that is *wrong* here, that is called
out — drifting to it causes real confusion, because this repo has two things that both
look like "the site".

## The two roots

| Term | Meaning |
|------|---------|
| **Source** | Everything under `src/`. The Vite root. The only thing a human edits. |
| **Build output** | `index.html`, `404.html`, `work/*/index.html`, `assets/` at the **repo root**. Generated by `yarn build`, committed to git, served by GitHub Pages. Never hand-edited. |
| **Static assets** | `CNAME`, `favicon.ico`, `img/` at the repo root. Not generated, not deleted by a build, mirrored into `src/public/` for dev. |

> "The repo root" is therefore **both** the deploy directory and the place source and
> config live. This is unusual and is the single most important thing to understand
> before changing the build. See [ADR-0003](docs/adr/0003-build-output-at-repo-root.md).

## Site structure

| Term | Meaning |
|------|---------|
| **Route** | A URL the site serves. Each is a real HTML file — there is no client-side routing. |
| **Entry point** | The `src/**/index.html` file for a route. Registered in `rollupOptions.input`; unregistered files are silently not built. |
| **Mount script** | `src/entries/<name>.tsx` — the `createRoot` call that mounts React into a route's `#root`. One per route. |
| **Page** | The `Page` component in `Layout.tsx`: header, `<main>`, footer. Not a synonym for route. |
| **Section** | The layout unit inside a page — `max-w-3xl`, optional small-caps heading. Home is a stack of these. |

Avoid **"page"** when you mean *route*, and avoid **"component"** when you mean *entry
point*. The distinction matters because adding a route touches three files.

## Content

| Term | Meaning |
|------|---------|
| **Case study** | A long-form account of one engagement, at `/work/<slug>/`. Structured `Context → Constraints → What I did → Trade-offs → Outcome`. Four exist: Cisco, Fidelity, HMH, Optum. |
| **Experience entry** | A dated row in the experience list. Every case study has one; not every entry has a case study (Fexco and WP Engine do not). |
| **Slug** | The stable identifier for a case study — `cisco`, `fidelity`, `hmh`, `optum`. Used as the route segment, the mount script name, and the `CaseStudyPage` selector. Changing one breaks a URL. |
| **Genericised** | Describing a client's system by problem shape rather than by its actual design. The standard every case study is held to. |

**Case study** is not a synonym for **project**. The retired 2014–16 items (Sitar
Player, SupremeBot, Datagram FTP) were *projects*; the site no longer has that concept.
See [ADR-0005](docs/adr/0005-sanitised-case-studies.md).

## Design system

| Term | Meaning |
|------|---------|
| **Token** | A CSS custom property in `globals.css` defined in `:root` and redefined in `.dark`, then exposed to Tailwind via `@theme inline`. |
| **Primitive** | A generated shadcn component in `src/components/ui/`. Tuned via tokens, not by rewriting. |
| **Theme bootstrap** | The inline `<script>` in every entry point that sets `.dark` before first paint. Its absence causes a light-mode flash. |

## Constraints, as nouns

Terms that name a rule rather than a thing. Each traces to an ADR.

| Term | Meaning |
|------|---------|
| **Zero third-party requests** | The site loads nothing from another origin — no analytics, CDN or webfonts. [ADR-0004](docs/adr/0004-no-third-party-requests.md) |
| **The privacy rule** | `docs/resume/` is gitignored because the repo root is the web root. Committing it publishes the CV and a phone number. |
| **Client-rendered** | Served HTML is a shell; prose is in the JS bundle. A known, accepted limitation with a known fix. [ADR-0006](docs/adr/0006-client-rendered-html.md) |
